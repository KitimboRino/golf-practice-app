## Recommended execution order

```
001  ──┬──▶ 002 ──▶ 004
       ├──▶ 003
       ├──▶ 005
       ├──▶ 006
       ├──▶ 007
       └──▶ 008
```

1. **001 first, always.** It adds `--ease-out` / `--ease-in-out` /
   `--dur-fast|base|slow`. Every other plan references those tokens.
2. **002 before 004.** Plan 004's reduced-motion block keeps the press-feedback
   `:active` selectors alive; those selectors are created by 002. (004 tolerates
   missing selectors — it says to drop unknown ones — but it is cleaner after
   002.)
3. **003, 005, 006, 007, 008** are independent of each other. Any order after
   001. 003 and 002 both touch some base `transition` declarations
   (`.more-row`, `.fault-row`, `.hist-open`, `.receipt-next`, `.datamenu button`)
   — whichever runs second must **merge** into the one `transition:` line, not
   add a second. Both plans call this out.
4. **005 touches `.tsx`** (`Toast.tsx`, `Confirm.tsx`); everything else is
   CSS-only except 006 (maybe `app/page.tsx`) and 007/008 (small `.tsx` edits).

## Not planned yet — additive opportunities

These came out of `find-animation-opportunities` (places that don't animate but
should). They are additive delight, not corrective, so they were left for a
separate decision. Run `improve-animations plan <description>` to spec any of
them.

- **Session Receipt** — the emotional payoff screen renders flat. `useCountUp`
  (already in `lib/useCountUp.ts`) on `.receipt-delta`, soft container entrance,
  check-tile pop. Highest-leverage additive item.
- **Warm-up step advance** — `.warm-now` content snaps between movements; key it
  by index and give a 200ms entry for sequence legibility.
- **Outcome long-press** — the 450ms hold-to-subtract has no visual indication;
  a `clip-path: inset()` fill during the hold would make it discoverable and
  prevent accidental subtracts.
