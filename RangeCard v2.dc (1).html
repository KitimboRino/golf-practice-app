# Handoff: Accessibility pass + first-run flow (RangeCard v2) ## Overview Two connected changes to the golf practice app: 1. **Turn 2 — Usable by everyone.** An accessibility pass over the existing screens: real buttons with labels, a shot strip that is readable without colour, 56px minimum targets, a light/high-contrast theme that survives 200% text, and an "Ease of use" settings screen for the things the OS can't know (gloves, one hand, plain language). 2. **Turn 3 — The first ten minutes.** A first-run flow that stops asking a beginner what they don't know: show the deal, teach the three log buttons by doing, run a no-score diagnostic session ("the read"), then reveal their miss pattern with a four-week plan already built. Nothing here forks the app into an "accessible version" or a separate onboarding product. Same data model, same five practice areas, same three-counter logging. ## About the Design Files The files in this bundle are **design references created in HTML** — prototypes showing intended look and behaviour, not production code to copy directly. `RangeCard v2.dc.html` is a design canvas: several 390x844 phone frames laid out side by side, each representing one screen. It is not an app shell. The task is to **recreate these screens in the app's existing environment** (the React + Dexie codebase this project already documents in `github.md`) using its established components, routing and persistence patterns. The one exception, called out below, is a set of literal code-level fixes (viewport meta, semantic elements, ARIA, focus rings, reduced motion) that should be applied directly to the existing components rather than rebuilt. ## Fidelity **High-fidelity.** Colours, type, spacing, radii and copy are final. Recreate pixel-accurately using the codebase's existing primitives. Where a value here disagrees with the current app, this file wins — the contrast and target-size numbers are deliberate. Two things are intentionally *illustrative* and must not ship as-is: - The "Screen reader says" card in frame 2a is an annotation for the developer, not UI. Implement it as a visually hidden `aria-live` region. - The frames render a fake status bar (9:41, wifi, battery).
